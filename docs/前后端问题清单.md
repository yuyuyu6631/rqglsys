## 四、已修复的问题（供参考）

### 4.1 前端已修复

| 问题 | 修复文件 | 修复方式 |
|------|----------|----------|
| `icon: any` 类型 | `Layout.tsx`, `OrderManage.tsx` | 使用 `LucideIcon` 类型 |
| `err: any` catch 错误 | `CylinderManage.tsx`, `OrderManage.tsx`, `Login.tsx`, `UserManage.tsx`, `AnnouncementManage.tsx`, `UserOrder.tsx` | 使用类型断言 `{ response?: { data?: { error?: string } } }` |
| useEffect 依赖警告 | `CylinderManage.tsx`, `SafetyManage.tsx` | 添加 `// eslint-disable-next-line react-hooks/exhaustive-deps` 注释 |
| 未使用变量 | `App.tsx` | 将 `catch (err)` 改为 `catch` |
| `statusMap` 潜在 undefined 访问 | `OrderManage.tsx`, `UserOrders.tsx` | 添加可选链操作符 `?.`，提供回退值 |
| `statusMap` 重复创建 | `UserOrders.tsx` | 将 `statusMap` 定义移到组件外部避免每次渲染重复创建 |

### 4.2 API 层已修复

| 问题 | 修复文件 | 修复方式 |
|------|----------|----------|
| `any` 类型参数 | `api.ts` | 定义具体接口：`CylinderParams`, `CreateOrderData`, `SafetyRecordParams`, `AnnouncementData` |

## 五、需要开发团队重点关注的问题

### 5.1 高优先级（必须修复）

1. **订单分配钢瓶逻辑** - 后端分配订单时自动锁定钢瓶，前端需要展示分配的钢瓶信息
2. **订单状态流转** - 确保前后端状态流转规则完全一致
3. **权限控制** - 前端路由权限和后端接口权限需要严格对齐

### 5.2 中优先级（建议修复）

1. **错误处理统一** - 统一前后端错误码和错误提示
2. **分页处理** - 目前列表接口都没有分页，大数据量时会出问题
3. **数据缓存** - 前端可以考虑添加合适的缓存策略

### 5.3 低优先级（可选优化）

1. **前端性能优化** - 大列表虚拟滚动、组件懒加载等
2. **后端接口性能** - 数据库查询优化、Redis 缓存等
3. **代码规范** - ESLint 规则进一步完善
